# Конспект: Эскейп-последовательности в C++

## 1. Что такое эскейп-последовательность?
**Эскейп-последовательность (escape sequence)** — это специальный символ или комбинация символов, используемая при выводе строк и отдельных символов. 

* Вводятся в строку с помощью **экранирующего символа `\`** (backslash, обратная косая черта), за которым следует управляющий символ или набор символов.
* Применяются для вставки непечатных управляющих символов ASCII, специальных знаков (кавычки, бэкслеш) или символов по их числовому коду.

---

## 2. Стандартные эскейп-последовательности

| Эскейп-последовательность | Описание | ASCII код (Hex) |
| :--- | :--- | :--- |
| `\0` | **Нулевой символ** (null terminator) | `0x00` |
| `\t` | **Горизонтальная табуляция** (Tab) | `0x09` |
| `\\` | **Обратная косая черта** (`\`) | `0x5C` |
| `\"` | **Двойная кавычка** (`"`) | `0x22` |
| `\'` | **Одинарная кавычка / Апостроф** (`'`) | `0x27` |
| `\b` | **Возврат на шаг назад** (Backspace, аналогично стрелке влево) | `0x08` |
| `\r` | **Возврат каретки** в начало строки | `0x0D` |
| `\n` | **Перевод строки** на новую | `0x0A` |
| `\a` | **Звуковой сигнал** (Alert / Bell) | `0x07` |

> **Примечание по кавычкам:**
> * Двойные кавычки внутри символьного литерала `char` (одинарных кавычек) можно не экранировать: `'\"'` или `'"'`.
> * Одинарную кавычку внутри строкового литерала (двойных кавычек) можно не экранировать: `"'"` или `'\''`.

### Пример использования:
```cpp
#include <iostream>

int main() {
    std::cout << "Табуляция:\tТекст\n";
    std::cout << "Строка с \\бэкслешем\n";
    std::cout << "Строка с \"кавычкой\"\n";
    
    // Экранирование в char
    char c1 = '"';   // Двойная кавычка без экранирования
    char c2 = '\'';  // Одинарная кавычка с экранированием

    // Шаг назад (\b)
    std::cout << "ABCDEF\b\b"; // Перемещает курсор на 2 символа назад
    
    // Звуковой сигнал
    std::cout << "\a"; 
    
    return 0;
}
```

## 3. Задание символов через коды ASCII

C++ позволяет вставлять символы напрямую по их шестнадцатеричному или восьмеричному коду из таблицы ASCII.

### Шестнадцатеричный код (`\xNN`)
* Синтаксис: `\x` + **1 или 2 шестнадцатеричные цифры** (0-9, A-F в любом регистре).
* Пример: `\x41` — символ `'A'` (код $41_{16}$).

### Восьмеричный код (`\OOO`)
* Синтаксис: `\` + **1, 2 или 3 восьмеричные цифры** (0-7).
* Пример: `\101` — символ `'A'` (код $101_{8} = 65_{10}$).
* Сам символ `\0` (нулевой символ) представляет собой частный случай восьмеричного кода.

### Пример кода:
```cpp
#include <iostream>

int main() {
    // Выведет "A+B=C"
    std::cout << "16-ричные коды: \x41\x2b\x42\x3d\x43\n";
    std::cout << " 8-ричные коды: \101\53\102\75\103\n";
    return 0;
}
```

## 4. Неоднозначности и ошибки при использовании

При записи эскейп-последовательностей с кодами могут возникать коллизии с последующими символами строки.

### 1. Проблема с нулевым символом `\0`
Строка `"ab\033ba"` воспринимается компилятором как строка с восьмеричным кодом `\033` (символ ESC), а не как нулевой символ `\0` и последующее число `33`.

**Решение:** Разбить строковый литерал на две части через пробел (компилятор C++ автоматически объединяет соседние строковые литералы):
```cpp
"ab\0" "33ba" // Сначала нулевой символ '\0', затем текст "33ba"
```

### 2. Проблема с шестнадцатеричным кодом `\x`
В шестнадцатеричном формате компилятор пытается считывать **все** идущие подряд шестнадцатеричные символы.

* `"\xFA"` — корректно (код `0xFA`).
* `"\xFFAA"` — **ошибка**, так как значение `0xFFAA` выходит за допустимый диапазон `0...255` (1 байт).

**Решение:** Разделять строки для разграничения кода и текста:
```cpp
"\xF" "A"   // Символ с кодом 0x0F, за которым следует буква 'A'
"\xFF" "AA" // Символ с кодом 0xFF, за которым следуют буквы "AA"
```
